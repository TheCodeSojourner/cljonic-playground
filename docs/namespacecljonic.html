The assoc free function associates a value with a key in a Map, or with an index in an indexed collection (Vector or String). The result is a distinct collection value; the source is unchanged.

Supported for Map (key/value association, replacing the value of an existing key), Vector (integer index association; an index equal to the current count appends when capacity remains), and String (the same index and append rule as Vector; see String for character validation and normalization policy). Set and Queue provide no associative capability and are rejected.

The variadic form assoc(collection, key₁, value₁, key₂, value₂, …) applies two or more key-value pairs left to right into the result, as if each were a separate assoc. A pair that cannot be applied (an invalid key, or a full-capacity map or append index) is skipped and the remaining pairs still apply.

Keys and stored values follow the safe implicit conversion rules.

Examples

#include "cljonic.hpp"
using namespace cljonic;
int main() {
// Compile-time demonstration.
constexpr auto m_const = assoc(hash_map<int, int, 4>(), 1, 100);
static_assert(m_const(1) == 100);
constexpr auto v_const = assoc(vector(10, 20), 1, 200);
static_assert(v_const(1) == 200);
constexpr auto m_multi = assoc(hash_map<int, int, 4>(), 1, 100, 2, 200);
static_assert(m_multi(2) == 200);

auto m_runtime = hash_map<int, int, 4>();
const auto m1 = assoc(m_runtime, 2, 200);

}

Supported for Map (an existing key can be replaced, or an absent key inserted when capacity remains), Vector (an integer index can be replaced, or an index equal to the current count can append when capacity remains), and String (the same index and append rule as Vector, with an invalid character returning false). The conj free function returns a collection with the supplied values added. Each operation returns a distinct collection value and preserves the source.

Supported for Vector, Set, Map, Queue, and String. Vector appends at the end. Queue enqueues at the rear. String appends at its logical count. For String, invalid characters are rejected at compile time and replaced with . at runtime; see String for character validation and normalization policy.

At full capacity, Vector, Queue, and String return unchanged copies. A full Set or Map also returns an unchanged copy when the element or key is absent.

Three arities are provided: conj(collection) returns an unchanged copy, conj(collection, value) adds one value, and conj(collection, value₁, value₂, …) adds two or more values left to right, so conj(c, x₁, x₂) equals conj(conj(c, x₁), x₂). Each value must be one the collection can hold, as described above; a value that does not fit because the collection is full is skipped.

Stored values follow the safe implicit conversion rules.

The equal free function compares one or more values for equality.

Equal compares values by their contents:

  • Calling equal with one value always returns true.
  • Two ordinary values compare equal when they are the same type and compare equal with == (e.g., int, a scoped enum, or a simple struct with an explicit or defaulted operator==). The comparison must not throw, so a type whose == can throw is not supported; pointers and unscoped enums are not supported either.
  • Vectors and Queues compare equal when they contain the same elements in the same order; producers (Ranges, Repeats, Cycles, Iterate, and Repeatedly) compare equal when they produce the same elements in the same order. When comparing producers, at most CLJONIC_COLLECTION_MAXIMUM_ELEMENT_COUNT_VALUE elements are compared, so this also works for two unbounded producers.
  • Maps compare equal when they hold the same entries, regardless of insertion order.
  • Sets compare equal when they hold the same elements, regardless of insertion order.
  • Strings compare equal when they hold the same characters.

Compared collections and sets must have matching element types, and compared maps must have matching key and value types. Collections are never compared to ordinary values. Values that cannot be compared stably, such as floating-point numbers, are not supported.

Iterate and Repeatedly values cannot be compared stably because their step is a callable, so they are not supported as map keys, set elements, or nested components. Standard-library range and container types are not supported at any depth.

Nested collections and composite values compare by the same rules; a nested producer that admits stable equality is compared by its stored parameters.

With more than two arguments, every adjacent pair is compared, from left to right, stopping at the first unequal pair.
