Safe implicit conversions

Arguments accept their declared types and numeric widening only when every source value is preserved. For example, short can widen to long long, and float can widen to double. Converting an integer to floating point also requires sufficient precision for every source integer. Floating-to-integer conversions and potentially narrowing conversions are rejected even when a particular literal fits.

Boolean, character, enum, pointer, and user-defined values do not implicitly change types. Convert deliberately before a call when needed, checking representability first; an unchecked cast does not establish safety. The same rules apply to construction, lookup, fallback, update, removal, and their preflight functions.

Where an operation requires nominal identity or exact types, safe numeric widening does not override that requirement. Conversion admission does not introduce implicit wrapping, callback substitution, or cross-type equality. Each operation documents its accepted domain where needed.

Some operations explicitly accept a broader input domain and validate representability or content before conversion. These exceptions are documented by the operation; they do not relax the default conversion rules.

External range imports require safe construction from the actual dereferenced elements and non-throwing traversal. For transformed ranges, the transformation must also be non-throwing.
